1. HIL 测试脚本是什么？

HIL（Hardware-in-the-Loop）测试脚本是一个 JSON 格式的测试套件， 定义了一系列 CAN 总线上的测试用例：发送帧、等待响应、断言信号值、注入故障等。

测试可以运行在四种模式下（详见 §6）： TraceReplay（回放 ASC/BLF 文件）、Hardware（真实 PCAN 硬件）、 VirtualEcu（虚拟 ECU 模拟器）、Matrix（多 ECU 矩阵）。

💡 一句话：写一个 JSON 文件，描述"发什么帧、等什么响应、断言什么值"， 工具帮你自动跑并出报告。

2. 测试套件结构

一个测试套件 JSON 文件包含以下顶层字段：

suite.json
{
  "name": "MyTestSuite",                   // 套件名称
  "cases": [ ... ],                              // 测试用例列表
  "globalCaseFixtureKeys": [],                    // 全局 fixture 键
  "suiteFixtureKeys": [],                          // 套件级 fixture 键
  "config": {                                      // 执行配置
    "failurePolicy": "ContinueAll",            // 失败策略
    "continueAfterSetupFailure": true
  },
  "timeoutMs": 0                               // 套件超时(0=不限制)
}

failurePolicy 可选值

值 行为
ContinueAll 失败后继续执行后续步骤和用例（默认）
StopCaseOnFailure 用例内失败后跳过剩余步骤，继续执行下一个用例
StopSuiteOnFailure 用例失败后停止整个套件

TestCase 结构

单个测试用例
{
  "id": "case_1",                    // 唯一标识
  "name": "TesterPresent_0x3E",       // 显示名称
  "description": "Send TesterPresent...", // 描述
  "preConditions": "ECU awake",        // 前置条件(可选)
  "steps": [ ... ],                       // 步骤列表
  "postConditions": "ECU still awake",   // 后置条件(可选)
  "tags": ["smoke", "uds"],           // 标签(可选)
  "timeoutMs": 0,                      // 用例超时(可选)
  "caseFixtureKeys": []                    // 用例级 fixture(可选)
}

3. CAN ID 格式

所有 CAN ID 使用统一的 JSON 对象格式：

{
  "raw": 2016,                    // 原始 ID 数值（十进制或十六进制）
  "format": "Standard",           // "Standard"(11位) 或 "Extended"(29位)
  "type": "Data"                  // "Data" | "Remote" | "Error" | "Status"
}
💡 常用 CAN ID 速查：
0x7E0 = 2016（诊断请求，Standard）→ 通常是 Tester 发给 ECU 的请求 ID
0x7E8 = 2024（诊断响应，Standard）→ ECU 回复的响应 ID
0x18FF60A2 = 419389602（Extended）→ 多 ECU 系统中的特定报文

4. 所有步骤类型详解

每个步骤通过 parameters.$kind 字段区分类型。步骤格式：

{
  "label": "可选标签",              // 可选，显示在结果树中
  "parameters": {
    "$kind": "sendFrame",           // 步骤类型，必填
    // ... 类型特定字段
  }
}

📤 SendFrame sendFrame

发送一条 CAN 帧到总线上。

id — CAN ID 对象 data — 字节数组，如 [2, 62, 0] fd — 是否 CAN FD（可选） extended — 是否扩展帧（可选）

⏳ ExpectFrame expectFrame

等待指定 CAN ID 的帧出现，支持数据掩码匹配。

id — 期望的 CAN ID dataMask — 数据匹配掩码（可选，null=只匹配 ID） timeoutMs — 超时时间

📊 WaitForSignal waitForSignal

等待 DBC 信号达到期望值（带容差，一直等到满足或超时）。

signalName — DBC 信号名 expected — 期望值 tolerance — 容差范围 timeoutMs — 超时时间

✅ AssertSignal assertSignal

立即断言信号值（不等待，直接检查当前值）。

signalName — DBC 信号名 expected — 期望值 tolerance — 容差范围

📏 AssertRange assertRange

断言信号值在 [min, max] 范围内。

signalName — DBC 信号名 min — 最小值 max — 最大值

⏱️ AssertResponseTime assertResponseTime

断言请求帧到响应帧之间的时间差不超过指定值。

reqId — 请求帧 CAN ID respId — 响应帧 CAN ID maxMs — 最大允许毫秒数

⚠️ AssertDTC assertDtc

断言 DTC（诊断故障码）存在或不存在。

dtcCode — DTC 码（可选，null=检查任意 DTC） expectPresent — true=期望存在，false=期望不存在

🚫 AssertNRC assertNrc

断言 ECU 返回了指定的否定响应码（NRC）。

serviceId — 请求的服务 ID expectedNrc — 期望的 NRC 值

⏸️ Delay delay

固定延时，等待指定毫秒数。

milliseconds — 延时毫秒数

💬 Comment comment

文档注释，不执行，不影响 pass/fail。

text — 注释文字

💥 InjectFault injectFault

注入故障条件（丢帧、延迟、数据损坏）。

canId — 目标 CAN ID faultType — DropFrame / DelayFrame / CorruptData probability — 概率 0~1 delayMs — 延迟毫秒数 direction — Send / Receive / Both

🧹 ClearFault clearFault

清除已注入的故障条件。

faultId — 故障 ID（null=清除所有）
⚠️ dataMask 的工作方式：
dataMask 是字节级别掩码，0 表示该字节不参与匹配，非 0 表示该字节必须匹配。 例如期望帧数据为 [0, 0x7E, 0, 0] 且掩码为 [0, 0xFF, 0, 0]， 则只检查第 2 个字节是否为 0x7E，其余字节忽略。

6. 四种运行模式

同一个测试套件 JSON 可以在不同模式下运行，取决于测试环境：

📼 TraceReplay 回放模式

从 ASC/BLF 录制文件中回放 CAN 帧，对历史数据运行测试断言。不需要真实硬件。

需要：Trace 文件 (.asc/.blf) 适用：回归测试、离线分析

🔌 Hardware 硬件模式

连接真实 PCAN-USB FD 硬件，在真实 CAN 总线上发送/接收帧。

需要：Hardware Channel (USB1..USB16) 适用：台架测试、整车测试

🖥️ VirtualEcu 虚拟 ECU

用 ECU 脚本 JSON 模拟一个虚拟 ECU，不需要真实硬件即可运行测试。

需要：ECU 脚本 (.json) 适用：开发阶段、CI 流水线

🧩 Matrix 矩阵模式

多 ECU 矩阵模式，用矩阵配置 JSON 管理多个 ECU 的交互测试。

需要：Matrix 配置 (.json) 适用：多 ECU 系统集成测试

7. 如何运行

在 GUI 中运行

  1. 打开 HIL 面板（工具 → HIL Testing）
  2. 选择 Mode（TraceReplay / Hardware / VirtualEcu / Matrix）
  3. 选择 DBC 文件（解析 CAN 信号名）
  4. 选择 测试套件 JSON（你写的 .json 文件）
  5. 根据模式填写其他路径（Trace 文件 / Hardware Channel / ECU 脚本 / Matrix 配置）
  6. 点击 Run 执行测试
  7. 查看 Results 标签页的 DataGrid + TreeView 结果

在 CLI 中运行

peakcan-host hil run \
  --dbc "path/to/your.dbc" \
  --suite "path/to/your-suite.json" \
  --mode TraceReplay \
  --trace "path/to/trace.asc"
💡 最佳实践：
• 先从 TraceReplay 模式开始，用已有的录制文件验证测试脚本逻辑
• 用 VirtualEcu 模式做 CI 自动化测试，不依赖硬件
• 通过后再切换到 Hardware 模式做真实硬件验证
• 每个用例加 tags 字段便于分类筛选
⚠️ 注意事项：
• CAN ID 的 raw 字段使用十进制数值，不是十六进制
• 0x7E0 = 2016, 0x7E8 = 2024, 0x18FF60A2 = 419389602
• dataMask 中 0 表示该字节不参与匹配
