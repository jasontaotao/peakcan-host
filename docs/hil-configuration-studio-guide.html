1. 什么是 HIL Configuration Studio？

HIL Configuration Studio 是一个 三栏式可视化配置窗口，替代了之前散落在 HIL 面板顶部的 多个 TextBox 和 ECU 脚本编辑器窗口。它把 HIL 测试全流程的配置集中到一个界面：

2. 如何打开

两种方式：

  1. 从 HIL 面板 — 在 HIL 测试面板点 Open ECU Editor， 会自动打开旧的编辑器窗口。如果已实现入口，也可以通过菜单 Tools → HIL Configuration Studio 打开。
  2. 从菜单栏 — 在 AppShell 菜单中，找到 HIL Studio 入口点击即可。

窗口是非模态的，可以跟 HIL 面板同时打开。关闭后再打开自动恢复上次状态。

3. Col 1: DBC Browser — 信号浏览器

这是整个 Studio 的 数据源。导入 DBC 文件后，消息和信号列表会同步提供给其他两栏使用。

操作步骤

  1. 点击 Open DBC... 按钮，选择 .dbc 文件
  2. 加载完成后，上半部分显示所有消息列表（ID、名称、DLC、发送节点、信号数）
  3. 点击某条消息，下半部分显示该消息的 信号详情
  4. 搜索框支持实时过滤，按名称或 ID 搜索

信号详情列说明

列 含义 示例
Name 信号名 EngineSpeed
Bits 起始位|长度@字节序(大端/小端)±符号 0|16@1+ (小端无符号, 16位)
Scale 比例因子 + 偏移量 0.1, 0
Range 物理值范围 [min, max] [0, 6553.5]
Unit 单位 rpm
Value Table 枚举值表名（可展开查看映射） State_Def
Comment CM_ SG_ 注释 // Engine speed in rpm
💡 关键联动：DBC 加载后，Test Suite Builder 里的 CAN ID 下拉、信号名下拉 都会自动填充。你不需要手动输入 "0x123" 或 "EngineSpeed"——从下拉列表选就行。

4. Col 2: Test Suite Builder — 测试套件构建器

这是写测试用例的地方。不需要写 JSON，通过 点按钮添加步骤 → 填参数 的方式完成。

界面布局

从上到下，从左到右：

  • 工具栏 — Open / Save / SaveAs / Suite 名称输入框
  • +Case / -Case — 添加/删除测试用例
  • 左侧列 — 用例列表（ListBox） + 步骤工具箱（Toolbox）
  • 右侧列 — 步骤列表（带 ▲ ▼ 排序和 Remove） + 属性面板

工作流：创建一个测试用例

💬 Comment → 📤 SendFrame → ⏳ ExpectFrame → ✅ AssertSignal
  1. 点 +Case 添加用例，输入名称
  2. 在左侧 Toolbox 区域，点 SendFrame 按钮添加步骤
  3. 右侧属性面板显示该步骤的参数，CAN ID 从 DBC 下拉选择，不用手写
  4. 再点 ExpectFrame / WaitForSignal / AssertSignal 等添加更多步骤
  5. 用 ▲ ▼ 按钮调整步骤顺序，Remove 删除不需要的步骤
  6. 点 Save 保存为 suite.json

12 种步骤类型

📤 SendFrame 发送帧

向总线发送一条 CAN 帧。CAN ID 从 DBC 下拉选，数据可用 Composer 拼装。

⏳ ExpectFrame 等待帧

等待指定 ID 的帧出现，支持数据掩码匹配。

📊 WaitForSignal 等待信号

等待 DBC 信号达到期望值（带容差、超时）。信号名从 DBC 下拉选。

✅ AssertSignal 断言信号

立即断言信号值，不等待。信号名从 DBC 下拉选。

📏 AssertRange 范围断言

断言信号值在 [min, max] 范围内。

⏱️ AssertResponseTime 响应时间

断言请求到响应的延迟不超过指定毫秒数。

⚠️ AssertDTC DTC 断言

断言 DTC 存在或不存在。

🚫 AssertNRC NRC 断言

断言 ECU 返回了指定的否定响应码。

⏸️ Delay 延时

固定延时等待。

💬 Comment 注释

文档注释，不影响 pass/fail。

💥 InjectFault 故障注入

注入丢帧/延迟/数据损坏/重复帧故障。

🧹 ClearFault 清除故障

清除已注入的故障。

SendFrame 的 Composer（数据拼装器）

选择 CAN ID 后，Composer 会显示该消息的所有信号，你填入信号值后自动计算 HEX 数据。 不需要手动计算字节排列和比例因子。

💡 信号名自动关联：WaitForSignal / AssertSignal / AssertRange 的 Signal 下拉框自动从已加载的 DBC 中提取所有信号，格式为 MessageName.SignalName — Comment，支持搜索过滤。

5. Col 3: ECU Simulator — 虚拟 ECU 编辑器

用于编辑 ECU 模拟脚本（VirtualEcu 模式），定义虚拟 ECU 的行为： 收到什么 UDS 请求、回复什么数据、怎么跳转状态。

界面布局

  • 工具栏 — Open / Save / SaveAs / Import ODX（从 ODX 文件导入）
  • ODX 导入参数 — ECU 名称、请求 ID、响应 ID
  • 脚本属性 — Name、InitialState、ReqID、RespID、Extended 复选框
  • 状态列表 — +S / -S 管理状态，点 +Trans 添加转移
  • 转移编辑 — ServiceId、SubFunction、Delay、Mask/Pattern、ToState、Response
  • DID 值编辑器 — 键值对编辑（DID → 字节数组）
  • 状态图预览 — 底部只读图形化状态机

工作流：创建一个 ValidEcu 脚本

  1. 填写脚本属性：Name（ECU 名）、ReqID（0x7E0）、RespID（0x7E8）
  2. +S 添加状态，如 "default"、"session"、"extendedSession"
  3. 选中一个状态，点 +Trans 添加转移规则
  4. 在下方编辑转移参数：
    • SID — 服务 ID（如 0x22、0x3E、0x10）
    • Sub — 子功能（可选）
    • ToState — 匹配后跳转到的状态（从下拉选）
    • Response — Static（固定数据回复）或 Dynamic（生成器）
    • Static data — 回复的 HEX 数据
  5. 在 DID Values 区域添加 DID 值（如 0xF190 → 01 02 03）
  6. 点 Save 保存为 ECU 脚本 JSON
  7. 切换回 HIL 面板，选 VirtualEcu 模式，选择刚才保存的脚本即可运行

状态机模型

💡 状态机逻辑：
每个状态定义一组转移规则（收到什么请求 → 回复什么数据 → 跳转到哪个状态）。 wildcard 是特殊状态名，表示"任何状态下都匹配"。 initialState 指定启动后的初始状态。

ODX 导入

如果已经有 ODX（Open Diagnostic eXchange）文件，可以直接导入： 填写 ECU 名称和 CAN ID，点 Import ODX，自动生成状态机规则。

⚠️ 注意：转移编辑中的 Response 支持两种模式： Static（固定 HEX 数据回复）和 Dynamic（使用生成器动态计算）。 生成器名称从已注册的插件列表中选择。

6. 完整工作流

一个典型的 HIL 测试配置流程：

1
打开 HIL Studio
Tools → HIL Configuration Studio
2
导入 DBC
Col 1 点 Open DBC... → 选择 DBC 文件。信号自动加载到其他两栏的下拉列表。
3
构建测试套件
Col 2 添加用例 + 步骤，参数从 DBC 下拉选。Save 保存为 suite.json。
4
配置虚拟 ECU（可选）
Col 3 编辑状态机、转移规则、DID 值。也可从 ODX 导入。
5
切回 HIL 面板运行
选模式 → 选择 suite.json / ECU 脚本 → 点 Run 执行测试。
💡 多模式兼容：同一个 suite.json 可以在 TraceReplay / Hardware / VirtualEcu / Matrix 四种模式下运行。测试逻辑不变，执行环境切换即可。
⚠️ 注意事项：
• 先加载 DBC，再构建测试套件——参数下拉列表依赖 DBC 内容
• ECU Simulator 编辑的脚本在 VirtualEcu 模式使用，其他模式不需要
• 保存后返回 HIL 面板，路径会自动同步到对应的 TextBox
