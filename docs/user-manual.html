1. 产品简介

PeakCan Host 是一款运行在 Windows 上的 WPF 桌面应用，用于对接 PEAK PCAN-USB FD（或 Pro FD）CAN/CAN-FD 硬件，提供通用的 CAN 总线监控、解码、手动发送、总线负载统计、AI 辅助分析、UDS 诊断与 HIL 测试能力。

核心能力

能力说明
多通道探测 & 连接枚举 PCAN-USB 1–16 通道，用户可选择任意通道连接
Trace 视图虚拟化 DataGrid 滚动展示所有接收到的帧（时间戳 / 通道 / ID / DLC / 十六进制数据 / 解析结果），支持 ID 前缀过滤
DBC 解码解析 .dbc 文件并填充消息表（发送方 / DLC / 信号列表），支持多路复用信号解码
Signals 视图对收到帧按 DBC 解码信号，实时显示原始值、物理值、Value-Table 解码名称
手动发送输入 CAN ID + 十六进制数据发送；支持 CAN-FD 与 11/29-bit 切换；支持周期性发送
帧录制将接收到的帧录制到 ASC（Vector ASCII）或 CSV 文件
Stats 视图1 Hz 图表，显示每秒帧数与总线负载百分比，含总帧 / 错误帧计数

2. 安装与前置条件

2.1 运行已发布的 EXE（推荐）

无需任何额外依赖：

  • 操作系统：Windows 10 (1809 及以上) 或 Windows 11
  • PEAK PCAN 驱动（官方下载页）
  • PCAN-USB FD（或 Pro FD）硬件一台

下载 PeakCan.Host.exe（约 66 MB，包含 .NET 10 运行时）后双击即可启动。

2.2 从源码运行 / 编译

  • .NET 10 SDK（官方下载）
  • 同上：Windows 10/11 + PEAK 驱动 + PCAN-USB FD 硬件

克隆源码后：

dotnet build PeakCan.Host.slnx -c Release

dotnet run --project src/PeakCan.Host.App

2.3 生成自包含单文件 EXE

dotnet publish src/PeakCan.Host.App -c Release -r win-x64 \

    --self-contained true \

    -p:PublishSingleFile=true \

    -p:IncludeNativeLibrariesForSelfExtract=true \

    -p:EnableCompressionInSingleFile=true \

    -o artifacts/win-x64/



artifacts/win-x64/PeakCan.Host.exe

3. 快速开始（5 分钟跑通）

  1. 插上 PCAN-USB FD，确认 PEAK 驱动已正确安装（设备管理器可见"PEAK-System PCAN-USB FD"）。
  2. 启动 PeakCan.Host.exe，主窗口默认打开 Trace 标签页。
  3. 点击工具栏上的 Probe 按钮 → 状态栏应显示 "Detected N channel(s)"，通道下拉列表显示检测到的通道。
  4. 从通道下拉列表选择要连接的通道，点击 Connect → 状态变为 "Connected"。
  5. （可选）菜单 File ▸ Open DBC... 选择 .dbc 文件 → Signals 标签页将随帧到达实时显示解码结果。
  6. 切到 Stats 标签页，可观察 1 Hz 折线图。
  7. 切到 Send 标签页，输入 ID 与数据，点击 Send 发送一帧。
  8. （可选）菜单 View ▸ Trace Viewer… 打开离线回放窗口，加载 .asc/.blf 文件查看信号曲线。
  9. （可选）菜单 View ▸ AI Chat 打开 AI 聊天助手，用自然语言查询信号信息。
没插硬件时 Probe 会怎样？通道列表显示 "No PEAK hardware detected: ..."，Connect 按钮自动禁用。

5. Trace（实时帧追踪）

图 2 — Trace 视图（默认标签）。每行对应一帧接收事件。

5.1 字段含义

列含义
Time帧接收时刻（本地时间，HH:mm:ss.ffffff）。
Ch硬件通道名（如 USB1 / USB2 / PCAN_PCIE_1），由通道下拉的选择决定。
IDCAN ID。Standard 11-bit 显示为 0xNNN（≤ 0x7FF）；Extended 29-bit 显示为 0xNNNNNNNN。
DLC数据长度码（0-8 为经典 CAN；CAN-FD 可达 64）。
Data十六进制字节序列（无分隔符）。
Decoded若该帧 ID 命中已加载 DBC 中某条消息，且当前帧不是错误帧，则显示"信号名=物理值"的简短摘要；否则显示 —。

5.2 行为细节

  • 行上限：MaxRows = 10 000。超出后从顶部 FIFO 丢弃最旧的帧。
  • 虚拟化：行/列均启用虚拟化（Recycling），10 k 行滚动无明显卡顿。
  • 性能：典型 1 Mbps 总线下帧率约 4 000 fps 时仍能稳定滚动；超过 8 000 fps 经典上限时可能略有延迟。
  • 错误帧：错误帧也会出现在列表（IsError 标志内部可见），但默认 Decoded 列对错误帧显示 —。
提示：使用滚轮或 Page Down 键快速跳到最新帧。DataGrid 选中行不会自动跟随——这避免了视觉跳动。

6. DBC（DBC 文件载入）

图 3 — DBC 视图（菜单 File ▸ Open DBC... 或本页 Open DBC... 按钮触发文件对话框）。

6.1 操作流程

  1. 点击 Open DBC... 按钮 → 弹出文件选择对话框（过滤器：*.dbc）。
  2. 选择文件后，解析在后台线程执行，状态文本显示 "Parsing..."。
  3. 解析成功后：
    • 消息列表被清空并填充新内容（每个 BO_ 一行）。
    • 状态文本变为 "Loaded N messages from <filename>"。
    • Signals 视图的旧条目被自动清除（避免与新 DBC 不一致）。
  4. 解析失败时，状态文本显示 "FAIL: <Code> <Message>"。

6.2 字段含义

列含义
ID消息的 CAN ID（来自 BO_ 行）。
Name消息名称。
DLCBO_ 行声明的数据长度。
Sender发送节点（来自 BO_ 第二个 token）。
Signals该消息下信号总数（不含多路复用/被多路复用信号之外的复用关系——即 DBC 中 SG_ 行计数）。
注意：重复加载同一 DBC 文件是允许的；每次都会触发完整重解析并清空 Signals 视图。 不支持热重载——如需重新加载需重新打开文件。

7. Signals（信号解码视图）

图 4 — Signals 视图：每帧解码后按 (Message, Signal) upsert，保证滚动状态稳定。

7.1 字段含义

列含义
Message所属消息名（来自 DBC BO_）。
Signal信号名（来自 SG_）。
Raw未应用 factor/offset 的整数值（0xN 格式）。
Physical应用 factor/offset 后的物理值（最多 3 位小数）。
Unit信号单位（来自 DBC SG_ 的单位 token；若为空则显示 —）。

7.2 行为细节

  • 前提：必须先在 DBC 视图加载一个 DBC 文件，否则 Signals 视图始终为空。
  • 解码规则：physical = raw * factor + offset。Intel/ Motorola 字节序、signed/unsigned、有符号数都按 DBC 规则解码。
  • 多路复用：M / m 多路复用信号在 v1.1.0 起完整解码；当前多路复用器值下激活的子信号会显示在 Signals 视图。
  • 更新频率：随帧到达实时更新；满负载下界面帧率受 WPF DataGrid 限制。
  • 跨线程：SDK 读线程触发解码，结果通过 WPF Dispatcher 投递到 UI 线程（你不会看到 NotSupportedException）。
为什么每行"原地更新"而不是追加？追加会让 DataGrid 反复创建/销毁行容器，引发滚动跳变与回收抖动。按 (Message, Signal) 原地替换既保留了最新值，又避免了视觉抖动。

8. Send（手动发送帧）

图 5 — Send 视图。ID 与 Data 均接受空格 / 连字符 / 大小写不敏感。

8.1 输入规则

字段规则
ID (hex)十六进制；非 Extended 模式最大 0x7FF（11 位），Extended 模式最大 0x1FFFFFFF（29 位）。越界或非十六进制时 Send 仍可点，但状态行显示 "Invalid ID: ..."，不会真的发送到总线。
Extended勾选 = 29-bit 帧格式；不勾 = 11-bit。
CAN FD勾选 = 设置 FDF 标志位（DLC 可达 64）；不勾 = 经典 CAN（DLC 0-8）。
Data (hex)十六进制字节序列；允许插入空格与连字符作分隔符（"DE AD-BE EF" 等价于 "DEADBEEF"）；奇数长度自动前补 0（"ABC" = {0x0A, 0xBC}）；空字符串或纯分隔符会被拒绝（显示 "Invalid data: ..."）。

8.2 操作流程

  1. 确保状态栏显示 "Connected"——未连接时 Send 仍可点但发送会失败。
  2. 填写 ID 与 Data，必要时切换 Extended / CAN FD。
  3. 点击 Send。
  4. 状态行更新：
    • 成功 → "Sent N bytes @ 0x<CanId>"（深绿）。
    • 失败 → "FAIL: <Code> <Message>"（深红）。
安全提示：手动发送会真实地发到 CAN 总线上。请确认已连接目标 ECU 的总线或具备终止电阻的总线段，避免对真实车辆/设备造成意外干扰。

8.3 错误码示例

场景状态行输出
未连接就点 SendFAIL: NotConnected ...
硬件错误（线缆断开等）FAIL: BusOff ... 或 FAIL: DriverError ...
DLC 越界（经典 CAN DLC > 8）FAIL: ParameterInvalid ...

9. Stats（总线统计）

图 6 — Stats 视图。蓝色 = FPS，红色 = 总线负载百分比；上为标题，下为 Sample 索引。

9.1 字段含义

元素含义
Total frames自连接以来累计收到的所有帧数（含错误帧）。
Error frames上述累计中被标记为 IsError = true 的子集。
Frames / sec（蓝线）过去 1 秒内收到的帧数。1 Hz 采样。
Bus load %（红线）过去 1 秒内总线占用率（由 PEAK SDK 报告）。

9.2 行为细节

  • 刷新频率：1 Hz（StatisticsService 后台定时器）。
  • 窗口大小：60 个样本 = 1 分钟历史；超出后丢弃最旧样本。
  • Y 轴：0..100（统一量程方便比对；FPS 在满负载时会"贴顶"，但用于看趋势而非绝对值）。
  • 跨线程：定时器线程产生快照，通过 Dispatcher 跳到 UI 线程更新集合，WPF 自动刷新图表。
提示：典型 1 Mbps 总线理论上限约 8000 fps；超过 50% 负载意味着总线接近饱和，需要注意响应延迟。

10. Script（脚本自动化）

Script 视图（v1.2.0 起）内嵌 CodeMirror 6 编辑器 + Roslyn 沙箱，允许在 UI 内编写/运行 C# 脚本，自动化重复的 CAN 总线测试场景（例：周期发帧、断言特定帧到达、清空 DTC）。

10.1 典型用法

  • 周期性发送：Send.PeriodicAsync(canId, data, intervalMs) 启动后台定时器。
  • 帧断言：订阅 Trace.Frames 集合变更，在指定时间窗内断言期望帧到达。
  • UDS 流程编排：调用 UdsClient.DiagnosticSessionControlAsync / ReadDataByIdentifierAsync 等，与 UDS 视图共享同一个 UdsClient 实例。

10.2 沙箱约束

安全模型：脚本在独立 AssemblyLoadContext + 受限 Permissionset 中执行，无法访问文件系统、网络、注册表。允许的 API：Send / Uds / Trace / Stats / Script 命名空间下的命令对象。

脚本的写入/读取位于 %LocalAppData%\PeakCan.Host\scripts\，文件名 *.csx。运行结果实时回写到右下角的输出面板（与 UDS 视图的 RichTextBox OutputLog 风格一致）。

11. UDS（UDS 诊断栈）

UDS 视图（v1.2.0 起）是 PeakCan Host 的核心诊断 UI，按 ISO 14229（UDS-on-CAN）实现应用层协议，运行在 CAN 之上。所有命令通过当前连接（UdsClient 单例）发往 ECU。

图 7 — UDS 视图：顶部 Session 条 + 3-tab TabControl + 底部共享 OutputLog。（v3.61.0 新增 Type 列与 Decoded fields）

11.1 Session 条（顶部）

控件行为
Default 按钮DiagnosticSessionControl 0x01 — 切到默认会话。
Extended 按钮DiagnosticSessionControl 0x02 — 切到扩展诊断会话（解锁 DID Read/Write）。
Programming 按钮DiagnosticSessionControl 0x03 — 切到编程会话（预刷写状态）。
TesterPresent 复选框勾选 = 后台每 2 秒发送 TesterPresent 0x3E 0x00 维持非默认会话；取消勾选停止循环。
SecurityAccess (Level 1) 按钮触发 SecurityAccess RequestSeed 0x01 → 调 IKeyDerivationAlgorithm.ComputeKey(...) → SendKey 0x02。成功时 Level: 0x01 显示在右侧。详见 §11.6。
Session: 文本当前会话名（Default / Extended / Programming）。
Level: 0xNN 文本当前认证等级。未认证时显示 (not authenticated)。

11.2 DIDs Tab

DataGrid 显示 DID 库（默认内置 5 个：VIN / PartNumber / SupplierID / HardwareVersion / SoftwareVersion），可由用户 JSON 文件扩展。

11.2.1 DID 数据源

DID 库按以下优先级合并：

  1. 内置默认（DidDatabase.BuiltInDefaults()）：5 个标准 VIN/PartNumber 等。
  2. 用户 JSON：%LOCALAPPDATA%\PeakCan.Host\uds-dids.json（可选）。同名 ID 覆盖内置，缺失追加。

JSON 格式示例：

{

  "dids": [

    { "id": 49152, "name": "BatteryVoltage", "lengthBytes": 2, "writable": false },

    { "id": 49153, "name": "CoolantTemp",   "lengthBytes": 1, "writable": false }

  ]

}

JSON 文件缺失或格式错误时不会抛异常——回退到内置默认，并在 Serilog 日志写一条 Warn。

11.2.2 DIDs Tab 字段（v3.61.0 更新）

列含义
IDDID 标识符（16-bit，hex 显示 0xNNNN）。
Name人类可读名。
Length数据长度（字节）。
Type v3.61.0数据类型描述（如 AsciiString[17B]、UInt32[16]、ByteField ×8、(no type)）。ODX 导入后自动推断。
R/W是否可写（来自 JSON 的 writable 字段，内置默认都为 R）。
Value最近一次 Read 后的解码值（v3.61.0 起显示物理值而非原始 hex，如 VIN 显示为字符串 "1HGCM..."，温度显示为 "90.0°C"）。

11.2.3 操作流程

  1. 选择 DataGrid 中的某一行 → 右侧详情面板填充 Name / Length / Type / Decoded fields。
  2. 点击 Read → UdsClient.ReadDataByIdentifierAsync(id) → 成功后 Value 列显示解码后的物理值（字符串、数字、物理量），详情面板显示逐字段解码详情。
  3. 若 DID 可写（Writable=true），可在 Write value (hex) 文本框输入字节，点击 Write → WriteDataByIdentifierAsync(id, bytes)。
  4. 每次操作的结果会追加到底部 OutputLog：Info（成功）/ Warn（NRC）/ Error（异常）。

11.2.4 DID 数据类型识别（v3.61.0）

ODX 导入后，DID 的数据类型信息自动解析：

  • 基础类型：UInt32、Int32、Float64、AsciiString、Unicode2String、ByteField、Unknown
  • 物理换算：IDENTICAL（raw = physical）、LINEAR（physical = (V0 + V1 × raw) / D0）、TEXTTABLE（枚举值查表）
  • 复合 DID：含多个字段的 DID 按字段逐一解码，右侧详情面板显示每个字段的 Name / Physical / Unit
  • 无 ODX 时：回退到原始 hex 透传（v3.39.0 及之前的行为）

示例：ODX 导入后读 VIN（0xF190）→ Value 列显示 1HGCM82633A123456（而非原始 hex 4C 53 56...）。

11.3 Routines Tab

DataGrid 显示 Routine 库（默认内置空数组），由用户 JSON 文件 %LOCALAPPDATA%\PeakCan.Host\uds-routines.json 加载（结构与 DIDs 类似，字段 id / name）。

列含义
IDRoutine 标识符（16-bit hex）。
NameRoutine 名（来自 JSON）。
Status当前状态（Idle / Running / Stopped）。
Result最近一次 Query 的结果字节序列。

操作：Start（RoutineControl 0x01）/ Stop（0x02）/ Query（0x03）。结果写入 OutputLog + DataGrid 的 Status / Result 列。

11.4 DTCs Tab

DTC 不走 JSON 文件——直接通过 ReadDtcInformationAsync(subFunction=0x02, statusMask=0xFF) 从 ECU 拉取。

列含义

Status1 字节 DTC 状态位掩码（0xNN）。

11.6 SecurityAccess 与 IKeyDerivationAlgorithm

SecurityAccess（Level 1）调用流程：

  1. UI 点击按钮 → UdsClient.SecurityAccessAsync(0x01)。
  2. Core 层先发 RequestSeed 0x01，收到 ECU 发的 seed。
  3. 调用已注册的 IKeyDerivationAlgorithm.ComputeKey(seed, level) 计算 key。
  4. 发 SendKey 0x02，等 ECU 响应正/负响应。
关键：当前默认注册的是 PlaceholderKeyAlgorithm——它原样回传 seed 作为 key，仅用于联调与冒烟测试。任何真实 ECU 都会拒绝（NRC 0x35 invalidKey）。

OEM 客户需要实现自己的 IKeyDerivationAlgorithm（接口在 PeakCan.Host.Core/Uds/IKeyDerivationAlgorithm.cs），并在 AppHostBuilder 中以单例注册替换占位实现。详见 附录 A §A.2。

12. Trace Viewer（离线 .asc/.blf 回放） v3.0.0

Trace Viewer 是 PeakCan Host 的离线回放窗口， 加载已录制的 .asc（Vector ASCII）或 .blf（Vector Binary Logging Format，v3.51.0 起）文件并按时间轴只读地查看信号变化曲线，绝不向 CAN 总线写入任何帧。

关键区分：
  • Trace Viewer（回放，v3.0.0）：加载 .asc / .blf → 解析 → 显示图表。无总线写入。
  • Replay（重发，v1.4.0）：加载 .asc → 通过 IReplayFrameSink 把帧重新写到总线上，影响真实总线状态。

12.1 启动方式

  1. 主窗口菜单 View ▸ Trace Viewer…（AppShellViewModel.ShowTraceViewerCommand）。
  2. 弹出非模态窗口（TraceViewerView），可与主窗口同时操作、独立关闭。
  3. 窗口内顶部工具栏：Open .asc/.blf（打开录制文件）+ Open DBC（可选，解析信号）+ 播放控件 ▶ / ⏸ / ⏹ + 速度下拉（0.25× / 0.5× / 1× / 2× / 4×）+ Loop 复选框 + 进度 scrubber。
  4. 窗口中部：横向 split（GridSplitter）。
    • 左侧：信号列表（按 (CAN ID, signal) 一行），列：Plot 复选框 / CAN ID hex / 信号名 / 最新值 / 单位。
    • 右侧：每个选中信号的子图（每个 PlotView 独立 Y 轴），共享 X 轴（0..TotalDuration）。v3.62.0 起使用 ScottPlot 5.x 渲染（替代 OxyPlot）。
  5. 窗口底部：状态栏 + Export CSV（导出所有已勾选信号样本，X = 时间，列为各信号值）。

13. AI Analysis（AI 辅助故障分析） v3.52.0

AI Analysis 面板是 Trace Viewer 窗口右侧 TabControl 的第 3 个 Tab，提供基于双锚（绿线/蓝线）的故障分析能力。支持本地 evidence 提取与可选的 LLM（DeepSeek）归因分析。

13.1 核心概念

概念说明
绿线锚点 v3.50.0故障时刻标记。拖拽任意子图中的绿色竖线 → 所有子图同步到该时刻。
蓝线锚点对照时刻标记。与绿线锚点配合，用于对比故障前后信号变化。
锁定 anchor 状态将当前绿/蓝锚点位置固定为 evidence snapshot 起点。双锚齐全才能锁定。
本地 evidence在 ±500ms 窗口内提取的确定性特征（信号跳变、异常值、帧丢失等），无需 LLM。
LLM 归因 v3.54.0可选：将 evidence 发送到 DeepSeek API 进行自然语言归因分析。

13.2 操作流程

  1. 设置绿线锚点：在 Trace Viewer 子图中拖拽绿色竖线到故障时刻。
  2. 设置蓝线锚点：在需要对比的时刻设置蓝线作为对照参考。
  3. 锁定 anchor 状态：点击工具栏 🔒 锁定 anchor 状态 按钮（双锚齐全才能锁定；蓝锚缺失弹提示阻止）。
  4. 运行分析：点击 🤖 运行分析 按钮触发 RunAnalysisAsync。AI Analysis 面板显示：
    • FaultEvent header：故障时刻 + 窗口信息
    • Evidence DataGrid：本地提取的确定性证据列表
    • Candidates DataGrid：候选关联因素
    • Summary 文本：分析结论摘要

13.3 诚实信号

AI Analysis 面板始终诚实标识分析结果的可靠性：

  • 顶部黄色横幅：本地推断（无归因；无 LLM 验证）
  • 未发现可靠关联时显示：未发现可靠关联（仅本地特征；无 LLM 归因）——这是合法输出，不是 error
  • 文案始终明确"无归因；无 LLM 验证"

13.4 LLM Provider（DeepSeek） v3.54.0

AI Analysis 面板支持可选的 DeepSeek LLM 归因分析：

  • API Key 配置：通过 AI Analysis 面板顶部的 API Key 输入区设置（v3.58.0 起支持 UI 内设置/验证/删除）
  • Windows Credential Manager：API Key 通过 Windows Credential Manager 加密存储（DPAPI），永不落盘明文
  • 流式输出 v3.59.0：SSE（Server-Sent Events）流式传输，首 token 延迟从 ~30s 降至 ~1s
  • 未配置 API Key：回退到本地仅分析报告，不调用 LLM

13.4.1 API Key 配置（v3.58.0）

AI Analysis 面板顶部包含 API Key 管理区域：

  • PasswordBox：安全输入 API Key（WPF PasswordBox，不回显明文）
  • 设置 按钮：保存 API Key 到 Windows Credential Manager
  • 验证 按钮：测试当前配置的 API Key 是否有效（无网络请求，仅状态探测）
  • 删除 按钮：从 Windows Credential Manager 移除 API Key
  • 状态指示：显示 NotSet / Configured（含上次更新时间）/ Removed
安全：API Key 永不写入日志文件；PasswordBox 防止 UI 中明文泄露；ApiKeyStatus 记录不包含 Value 字段。

13.4.2 流式输出（v3.59.0）

DeepSeek Provider 支持 SSE 流式输出：

  • 运行分析后，AI Analysis 面板的 Summary 区域会逐 token 增量更新
  • 首 token 延迟约 1 秒（非流式模式约 30 秒）
  • PartialSummary / PartialEvidenceId / FinalResult 三种增量更新类型
  • 取消操作（点击停止）会立即中断 HTTP 请求，不等待响应完成

13.5 空状态

AI Analysis 面板打开时显示空状态提示：

  • 无锚点锁定：提示"拖拽绿/蓝锚点并锁定以开始分析"
  • 已锁定但未分析：显示"锚点已锁定。点击运行分析按钮"

13.6 已知限制

  • LLM 分析需要网络连接到 DeepSeek API（中国区用户可能需要代理）
  • Azure / Ollama Provider 尚未实现（接口已预留）
  • Token 用量持久化尚未实现（仅日志记录）
  • API Key 无密钥轮换 UI（单 key 模型）

17.3 如何获取完整诊断信息

  1. 复现问题一次。
  2. 打开日志目录：Win+R → 输入 %LocalAppData%\PeakCan.Host\logs。
  3. 找到当天日期的 peak-yyyy-MM-dd.log，把异常堆栈 + 时间戳附在 bug 报告里。

18. FAQ & 已知限制

18.1 FAQ

Q1: 能否连接多块 PCAN-USB FD 或多通道?

A: 可以。v1.1.0 起 Probe 枚举 PCAN-USB 1–16 通道，工具栏的通道下拉显示所有检测到的通道，可任意选择后 Connect。当前限制：同一时刻单连接（多通道并行收发不在 v3.x 范围）。

Q2: 能否录制总线数据供后续回放?

A: 录制 可以（v1.1.0 起，Record 服务支持 ASC + CSV 输出）。回放已提供：v1.4.0 起 Replay 服务实现，v2.1.4 起 View ▸ Replay 菜单可直接打开。离线查看信号曲线走 Trace Viewer（v3.0.0 起，View ▸ Trace Viewer…）。

Q3: BLF 文件能否加载?

A: 可以。v3.51.0 起 Trace Viewer 支持加载 Vector BLF（Binary Logging Format）文件。BLF 是 Vector CANalyzer/CANoe 的二进制日志格式，体积更小、解析更快。

Q4: 多路复用（M / m）信号能否解码?

A: 可以。v1.1.0 起 DbcParser 识别 M / m 修饰符，SignalDecoder 按多路复用器值动态选择被复用信号。

Q5: AI 分析需要什么配置?

A: 本地分析（无 LLM）不需要任何配置。如需 LLM 归因分析，需要在 AI Analysis 面板设置 DeepSeek API Key（通过 Windows Credential Manager 加密存储）。流式输出（v3.59.0）开箱即用。

Q6: AI Chat 和 AI Analysis 有什么区别?

A: AI Chat（v3.62.0）是自然语言交互的聊天助手，通过工具调用查询信号信息、管理分组。AI Analysis（v3.52.0）是 Trace Viewer 内的故障分析面板，基于双锚（绿/蓝线）提取证据，可选 LLM 归因。两者共用 DeepSeek Provider。

Q7: UDS SecurityAccess 直接能工作吗?

A: 不能直接。默认注册的是 PlaceholderKeyAlgorithm——原样回传 seed，仅用于联调；真实 ECU 会返回 NRC 0x35 invalidKey。OEM 客户需要实现 IKeyDerivationAlgorithm 并在 AppHostBuilder 替换。详见 §11.6。

Q8: DID/Routine 库能不能扩展?

A: 可以。%LOCALAPPDATA%\PeakCan.Host\uds-dids.json + uds-routines.json 可放置用户 JSON，缺失/格式错误时回退到内置默认。详见 §11。

Q9: HIL 测试框架需要什么?

A: HIL 测试需要已连接的 PCAN-USB FD 硬件。CLI 模式（peakcan-hil）也需硬件接入，适合 CI 自动化。

Q10: 能否在 UI 关闭后保留 TesterPresent?

A: 不能。TesterPresent 后台循环由 SessionPanelViewModel 持有，VM 是 DI 单例直到进程退出。切换会话前请手动取消勾选。

A.2 关键决策

决策理由
.NET 10（非 8）开发机仅有 10.0.300 SDK；自包含发布后目标机不需任何运行时。
Peak.PCANBasic.NET 5.0.1（非 Peak.Can.Basic）旧的 Peak.Can.Basic 在 nuget.org 上不可寻；Peak.PCANBasic.NET 是 PEAK 官方替代（12.7 万次下载）。
OxyPlot.Wpf → ScottPlot 5.x v3.62.0Trace Viewer 图表渲染引擎从 OxyPlot 迁移至 ScottPlot 5.x，支持渐进填充引擎，渲染性能显著提升。Stats 视图仍使用 OxyPlot。
DeepSeek LLM Provider v3.54.0AI Analysis 和 AI Chat 共用 DeepSeek Provider 作为 LLM 后端。API Key 通过 Windows Credential Manager 加密存储。SSE 流式输出（v3.59.0）降低首 token 延迟。
多通道探测 + 单连接Probe 枚举 1–16 通道并填充下拉，但同一时刻仍只允许单连接。
VM 部分 IDisposable多数 VM 仍是 DI 单例不实现 IDisposable；但 SessionPanelViewModel 持有 TesterPresent 后台 CTS，实现 IDisposable 复位。当前 DI 容器不调用 Dispose()。
IFileDialogService 抽象抽取为接口 + WpfFileDialogService 实现，所有用户取消测试改为真实断言。
IKeyDerivationAlgorithm 抽象 + PlaceholderKeyAlgorithmUDS SecurityAccess 的 seed-to-key 算法因 OEM 而异。提供占位实现让 UI 联调可跑通；OEM 客户需自行实现并替换。
UDS 4 面板 orchestrator 模式拆为 4 个 panel VM（Session / DID / Routine / DTC） + orchestrator，每个 panel VM 通过 IUdsPanel.AttachLog(...) 接口共享一个 OutputLog。
AI Analysis 双锚模式 v3.52.0绿线 + 蓝线双锚作为故障/对照时刻，本地 evidence 提取与可选的 LLM 归因分离。诚实信号标识（黄色横幅）始终明确分析局限性。
