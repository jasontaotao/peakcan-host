# v3.69.0 发布说明 — 小版本：UDS 通讯参数可配置 + 离线日志分析

**发布日期:** 2026-11-26

## 概览

本版交付两条主线，外加一项性能修复：

1. **UDS 通讯参数可配置** — 诊断 CAN ID 与 P2 / P2* / N_Bs / N_Cr 可在界面编辑、运行时立即生效、跨重启记忆。同时修正两个长期存在的协议缺陷。
2. **离线日志分析** — 加载 ASC/BLF，按 ISO-TP 重组、配对 UDS 事务、结合 ODX 定义生成报告，支持导出与 AI 交接。
3. **Trace 高帧率积压修复** — 解码回填改为合批写回。

## 新功能

### UDS 通讯参数（可编辑 + 持久化）

- **可编辑表单** — 「通信参数」面板上半保持只读展示（诊断栈 / 刷写副栈当前生效值），下半新增可编辑区：请求 ID、响应 ID、功能寻址 ID、扩展帧开关、P2、P2*、N_Bs、N_Cr。
- **运行时立即生效** — 改完点「应用」即刻生效，不需要重启。`IsoTpLayer` 内部用不可变快照原子替换 CAN ID 配置，接收过滤与发送路径同时切换，不存在「接收用新 ID、发送用旧 ID」的撕裂窗口。
- **重配仲裁** — 有诊断请求或多帧传输在途时**拒绝**重配而不是排队：多帧传输中途换 ID 会让首帧用旧 ID、后续帧用新 ID，ECU 丢掉整包。界面提示稍后重试。
- **跨重启记忆** — 配置落盘到 `%APPDATA%\PeakCan.Host\uds-transport.json`。保存失败会如实上报，不谎报成功；文件损坏时重命名 `.bad` 留档而非直接覆盖。
- **三态来源标注** — P2 / P2* 的来源明确区分「ECU 0x10 协商」「用户配置」「本地默认」。改前是两态，用户配过之后仍显示「本地默认」，让人以为没生效。
- **离线页继承地址** — 离线分析页的地址输入框从同一份配置初始化，不必每次手敲。在线配置变更只在用户没改过离线地址时同步（否则会冲掉为另一台 ECU 手输的值）。

### 离线日志分析

- **加载** — ASC / BLF 文件，带显式大小与条数上限。
- **ISO-TP 重组** — 处理孤立帧与序列错误，统计口径闭合（分类计数之和等于总数）。
- **事务配对** — 请求与响应配对并做响应校验；跟踪会话时序与耗时。
- **ODX 降级可见** — 定义文件加载状态显式呈现，缺定义时按降级路径解析而不是静默失败。
- **报告与导出** — 不可变报告 + 噪声统计；导出 Markdown/CSV，敏感信息脱敏。
- **AI 交接** — 报告可交给现有 AI 聊天继续分析。

## 缺陷修复

### P2* 单位换算（自 2026-06-22 起存在）

ISO 14229-1 规定 ECU 在 `0x10` 正响应里报告的 P2 是毫秒、P2* 是 **10 ms 单位**。客户端读 P2* 时漏乘 10，导致协商后的超时被缩放成实际值的 1/10。

**影响**：典型 ECU 回 5000 ms 会被算成 500 ms。ECU 在擦除 Flash 时常回 `NRC 0x78`（"还在处理"），客户端因此提前 10 倍放弃——这是最可能被打中的场景。

**行为变化**：修复后，刷写时原本"快速失败"的场景会等更久才报错。这是正确行为。

### N_Cr 超时从未真正生效

ISO-TP 多帧重组时，若连续帧（CF）迟迟不到，应按 N_Cr 超时放弃重组。原实现读了 `_receiveTimeout` 却从未使用，创建的取消源也没设超时——重组状态因此不会被超时清理，只能等下一帧首帧覆盖。

同时修正了 watchdog 的"取代判定"：原方案用 generation 计数器，而该计数器来自序列号（`& 0x0F` 回绕），存在别名碰撞导致旧回调误清新缓冲区的风险。改为实例身份比较。

### 断连后状态残留

断线重连另一台 ECU 后，面板继续显示上一台协商的时序值并标注「ECU 0x10 协商」；STmin/BS 的「是否收到过流控帧」一旦置真永不复位。这类"标注是假的"比数值错更难查——用户会相信标注。

现在断连复位统一走一个入口，原子协调会话状态、时序、ISO-TP 收发状态与在途请求。

### 只改时序不再踢回默认会话

修改通讯参数时若只改超时值，本地模型不应把会话状态重置为「默认」——ECU 那边可能还停在编程会话里。现在只有寻址真的变化才走完整复位。

### 刷写栈时序跨运行残留

刷写用的 UDS 栈复用同一个超时对象，第一次刷写协商的 P2 / P2* 会残留到第二次。若第二次禁用了会话切换步骤，就会用上一台 ECU 的值。现在每次刷写各建一份。

### Trace 高帧率 UI 积压

解码 worker 原本每帧一次 UI 调度（8k fps 约 8000 次/秒），高帧率下界面卡顿。改为有界缓冲 + UI 侧 33ms 批量写回；信号值缓冲按 (消息, 信号) 合并，图表样本按时间戳升序（修复时间差下溢成 1.8e13 秒的显示异常）。

### ZLG 设备枚举

USBCANFD 枚举与 I/O 改用基于句柄的 ZCAN API。

## 技术债清理

- 删除 `UdsTimer` 上两个零读取的死字段（`S3Timeout` / `P3StarTimeout`）；S3 相关时长统一到 `UdsSession.S3Timeout`。
- 修正 `UdsSession.ResetS3Timer` 会把保活周期拉成 S3 超时且不再重复的缺陷——原实现让 `StartS3KeepAlive` 的间隔参数只在第一个周期生效。
- 修正刷写面板一处声称 profile 保存了时序参数的错误注释（`FlashProfile` 无该字段）。
